# How BLINCS protects your results

BLINCS computes signatures matching [`SPEC.md`](SPEC.md) with zero `unsafe` Rust and one runtime dependency (`blake3-servil = "=0.10.0"`). When a check detects a broken contract, the process stops rather than returning a silently broken signature.

## What we check

| Layer | How we check it | What remains outside it |
|---|---|---|
| Byte-level specification conformance | An independent pure-Python implementation ([`reference/blincs.py`](reference/blincs.py)) with its own from-spec BLAKE3 ([`reference/blake3.py`](reference/blake3.py), verified against all 35 official BLAKE3 test vectors in three modes) cross-checks the Rust crate in both directions: Rust reproduces `test_vectors/reference-signature-1.bin` byte for byte, and Python verifies Rust signatures across empty, small, 64 KiB, and 512 KiB+ messages. | Shared misunderstandings present in both `SPEC.md` and the two implementations. |
| Memory safety, lints & trusted base | `#![forbid(unsafe_code)]`, `Cargo.toml` denies `unused_must_use`, `unreachable_patterns`, `clippy::cast_possible_truncation`, `cast_sign_loss`, and `cast_possible_wrap`. [`tools/counts.py`](tools/counts.py) enforces zero `unsafe` blocks, zero `debug_assert!`s, zero truncation allows, zero print macros, and zero `Drop` implementations across shipped `src/`. One runtime dependency (`blake3-servil = "=0.10.0"`, 10 crates total in `Cargo.lock`, all BLAKE3 + SHA-256 hashset-verified) and zero dev-dependencies. | Safety and correctness of `blake3-servil` and its assembly kernels (separately checked by BLAKE3-Servil's own symbolic proofs and tests). |
| Types carry their rules | Distinct private-field key newtypes (`SecretKey`, `PublicKey`, `ContentKey`, `MessageKey`, `SaltKey`, `RandomizerKey`, `RunKey`), `TweakKind` and `Layer` enums, 48-bit `TreeIndex`, 33-bit `LeafAddr`, 10-bit `ForsIndex`, and checked `Pos::new` make cross-key mixups and out-of-range coordinates unrepresentable. | Caller-supplied 32-byte signing seeds (not entropy-tested by `from_seed`). |
| Verifier checks & planted-fault controls | Unit tests exercise WOTS+ nibble/checksum boundaries (`0..=480`), `parse_digest` 10-bit FORS index and 33-bit `leaf_addr` extraction, `advance_chains` zero/partial/early-finish/full lengths, checked constructor boundaries, bit-0 flips at representative offsets across every signature region (salt, randomizer, all 16 FORS trees, all 4 hypertree layers), wrong verifying keys, and wrong signature/key lengths. [`tools/controls.py`](tools/controls.py) removes 16 protections one by one and verifies each targeted test actually runs and fails (with a 120 s timeout). | Predicates not listed in `tools/controls.py`. |
| Streaming I/O, panic reuse & stack budget | Tests verify slice-vs-reader equivalence across 15 length boundaries (`0` through `1 MiB + 19`) spanning the on-core `< 16` KiB stack fast path, the zero-copy `Pipeline` streaming path ($\ge 16$ KiB, zeroing each newly acquired room slice before `Read::read`), and the multi-core slice threshold ($\ge 512$ KiB), with fragmented reads, `EINTR` injection, mid-stream `Pipeline::abort` recovery, `u64::MAX` length-overflow helper checks, fail-stop checks on `Read` returning `n > buf.len()`, `catch_unwind` reuse after a panicking `Read`, snooping checks across both stack and `Pipeline` rooms, re-entrant `Read` callbacks from both paths, and a bounded **128 KiB thread-stack** test on the optimized test profile. | Pathological `Read` implementations that never return (infinite loops); unoptimized debug-build stack usage. |
| Startup randomness state | Tests check explicit `create` (refuses overwrite and dangling symlinks, `0o600` on Unix, distinct OS seeds), `initialize` (rejects directories, `/dev/null` non-regular files, missing, short, oversized-with-valid-magic, wrong-magic, and counter-exhausted files without modifying a byte; serializes 8 concurrent threads under `flock`), `mix` exact cross-check against Python, fresh-thread public `sign`, and draw counter exhaustion. | Unix-only signing boundary; filesystems without working advisory locks, symlinks to existing regular files in untrusted directories, `fork()` without `exec()`, and live VM snapshot cloning (callers must re-run `initialize`). |
| Process isolation (`cargo-nextest`) | Every test runs in its own process via `cargo-nextest` (`.config/nextest.toml`). Plain `cargo test` fails immediately on the sentinel test `aaa_require_nextest`. Separate fresh-process tests verify entry points initialize `blake3-servil`. | Doc examples run under `cargo test --doc` (rustdoc already isolates each example in its own process). |
| Mutation testing | [`tools/mutants/check.py`](tools/mutants/check.py) runs `cargo-mutants` in `[profile.mutants]` (release optimization, no debug assertions or overflow checks) across all of `src/`. Every viable mutant must be caught by a test or justified in [`tools/mutants/known.txt`](tools/mutants/known.txt); timeouts and stale known entries both fail the gate. | Mutants classified in `tools/mutants/known.txt` (functional output equivalence, dispatch/resource-only changes, or directory-sync durability). |
| Self-check on signing | `SigningKey::sign` and `sign_reader` run `VerifyingKey::verify_short` over every finished signature (binding serialized salt `sig[..16]` to `short[..16]` and recomputing all FORS + hypertree paths) before returning it (~25 µs, ~3.5% of signing time) and panic on mismatch. | External stream corruption before hashing; hardware faults that corrupt both signing and self-verification symmetrically. |
| Performance measurements | [`bench/`](bench/) measures wall time, core cycles, instructions, clock frequency, and background CPU load together via `bench-hashes`'s `clocks` crate, summarizing runs in exact integers. | Machines other than those explicitly reported; thermal or host interference on non-dedicated hardware. |
| Cross-family contract review | Round 1 (`0.1.0`) and Round 2 (`6e4ded7`, `12 + 3×7`) automated reviews by `openai/gpt-6.2-astra-pro` archived unedited in [`audits/`](audits/); concrete code, pool, contract, and documentation findings fixed and covered by regression tests. | Independent human cryptographic review and formal security proof of the full BLINCS instantiation (not yet performed). |

## Reproduction commands

```sh
cargo fmt -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo nextest run --locked
cargo test --doc --locked
python3 reference/blake3.py
python3 tools/controls.py
python3 tools/mutants/check.py
python3 tools/land.py
```
