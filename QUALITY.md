# How Signet (`BLINCS-128-7x5`) protects your results

Signet computes `BLINCS-128-7x5` signatures matching [`SPEC.md`](SPEC.md) with zero `unsafe` Rust and two runtime dependencies (`blake3-servil-core = "=0.11.0"` and `getrandom = "=0.4.3"`, strictly single-threaded with zero background worker threads). Verification is fail-closed (`Result<(), InvalidImprint>` / `Result<(), VerifyError>`), and when an internal check detects a broken contract, the process stops rather than returning a silently broken signature.

## Timing and secret independence

Signet is written so that secret material does not steer branches or memory indices in its Rust code:

1. **Signing branches and indices depend only on public or reconstructible values.** The FORS tree indices (`fors_indices`), hypertree address (`leaf_addr`), Merkle sibling directions, and WOTS+ chain step counts (`digits(node)`) are all derived from `D`, `salt`, `randomizer`, `ctx`, and tree roots that are reconstructible from the message, context, and imprint. (For confidential messages before publication, WOTS+ step counts vary with the message-derived tree roots.)
2. **Secret material is only copied or hashed.** `seed`, `SecretKey`, `salt_key`, `randomizer_key`, `run_key`, `keygen_key`, `draw`, and unrevealed FORS/WOTS+ secrets are never branched on, sorted by, or used as array indices; they are passed directly into `blake3-servil-core`.
3. **Underlying hash kernels and hardware limits.** `blake3-servil-core` symbolically proves its assembly kernels branch- and address-independent of keys and inputs, while leaving CPU data-independent timing modes (Arm `DIT`, Intel `DOITM`) to the calling thread or OS. Power/frequency side channels (such as Hertzbleed) and data-dependent prefetchers without `DIT` (such as GoFetch on Apple M1–M3) sit outside software proofs; callers requiring hardware timing guarantees should enable `DIT`/`DOITM` at the thread or platform level.

## Bugs these steps found

Concrete defects found during development and cross-family reviews, and the checks that keep them from returning:

1. **Recycled reader buffer bytes visible to `Read::read` (Round 2 review).** Earlier `Pipeline` code exposed recycled buffer bytes to safe `Read` implementations. Fixed by zeroing every buffer slice before `read` in `content::fill_buf` (and later removing `Pipeline` entirely in favor of a single local 16 KiB stack buffer); guarded by `test::reader_never_sees_previous_callers_bytes` and planted-fault control #9.
2. **Imprinting self-check did not independently bind `imprint[..16]` to `short[..16]` (Round 2 review).** `verify_short` hashed `short` without comparing `imprint.salt()` against `short[..16]`. Fixed in `SignetId::verify_short`; guarded by dedicated test `test::verify_short_rejects_mismatched_salt_against_short` and planted-fault control #5 in `tools/controls.py`.
3. **Unchecked `u64::MAX` stream length (Round 2 review).** Fixed via `checked_add_stream_len`; guarded by `test::checked_constructors_reject_out_of_range_values`.
4. **Reference validation skipped under `python3 -O` (Round 2 review).** `reference/blincs.py` used `assert` for input length checks, which `-O` strips. Replaced with explicit `ValueError`/`TypeError` checks; guarded by the `python3 -O` check in `tools/land.py` (which also refuses `-O` itself).
5. **Missing `#[must_use]` on `verify`/`verify_reader` and loose `Pos::new` tree bound (Round 3 review).** Fixed with `#[must_use]` annotations, fail-closed `Result` return types, and exact per-layer `tree < layer.trees()` (`tree == 0` at the top layer); guarded by `test::checked_constructors_reject_out_of_range_values`.
6. **Hypertree Merkle left/right rule and `FEW_ROOT` wording in `SPEC.md` (TypeScript verification & Round 3 review).** Clarified explicitly in `SPEC.md` so cold readers never have to infer hypertree sibling order or `FEW_ROOT` tweak fields.
7. **Concurrent POSIX `readdir` rotation race in lock-free `Randomness::initialize` (landing stress test).** When overlapping startups unlinked every listed seed between `read_dir` and `open` (or shifted entries past the `readdir` cursor), `initialize` could falsely report an empty directory. Fixed in `read_seed_entries` by re-scanning up to 16 times; guarded by an 8-thread × 10-round (80 overlapping rotations) stress test in `src/test.rs`.
