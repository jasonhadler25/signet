# How BLINCS protects your results

BLINCS computes signatures matching [`SPEC.md`](SPEC.md) with zero `unsafe` Rust and one runtime dependency (`blake3-servil = "=0.10.0"`). When a check detects a broken contract, the process stops rather than returning a silently broken signature.

## What we check

| Layer | How we check it | What remains outside it |
|---|---|---|
| Byte-level specification conformance | An independent pure-Python implementation ([`reference/blincs.py`](reference/blincs.py)) with its own from-spec BLAKE3 ([`reference/blake3.py`](reference/blake3.py), verified against all 35 official BLAKE3 test vectors in three modes) cross-checks the Rust crate across `test_vectors/reference-imprint-1.bin` and `test_vectors/edge-vectors.json` (empty, 1 B, 1,024 B chunk boundary, and 16,385 B multi-chunk + bit-32 `leaf_addr`), plus 64 KiB and 512 KiB+ messages. An educational, blind spec-only TypeScript verifier ([`reference/blincs.ts`](reference/blincs.ts)), written strictly from `SPEC.md` by a separate model family with no access to `src/` or `reference/blincs.py`, independently verifies all checked-in vectors and `mix`/`draw` outputs. | Shared assumptions present in `SPEC.md` itself or in the BLAKE3 standard. |
| Static & dynamic domain separation | [`tools/domain_sep.py`](tools/domain_sep.py) statically parses `src/params.rs` and `SPEC.md` to verify all 9 `CTX_*` strings and all 9 `TweakKind` byte tags (`1..=9`) are distinct and match `SPEC.md`, verifies every shipped `tweak(TweakKind::...)` call site pairs secret tweaks exclusively with `SecretKey` and public tweaks exclusively with `PublicKey`, proves wire-field bit-width bounds across the full $2^{33}$-leaf parameter space, self-tests with 3 planted faults, and dynamically traces `reference/blincs.py` to confirm zero duplicate tweaks and zero `K_sec` calls during verification. | Cryptographic collision/preimage resistance of BLAKE3 itself. |
| Memory safety, lints & minimal base | `#![forbid(unsafe_code)]`, `Cargo.toml` denies `unused_must_use`, `unreachable_patterns`, `clippy::cast_possible_truncation`, `cast_sign_loss`, and `cast_possible_wrap`; `verify`, `verify_reader`, `imprint`, and `from_bytes` are `#[must_use]`. [`tools/counts.py`](tools/counts.py) enforces zero `unsafe` blocks, zero `debug_assert!`s, zero truncation allows, zero print macros, and zero `Drop` implementations across shipped `src/`. One runtime dependency (`blake3-servil = "=0.10.0"`, 10 crates total in `Cargo.lock`, all BLAKE3 + SHA-256 hashset-verified) and zero dev-dependencies. | Safety and correctness of `blake3-servil` and its assembly kernels (separately checked by BLAKE3-Servil's own symbolic proofs and tests). |
| Types carry their rules | Separate private-field `SecretKey` and `PublicKey` newtypes prevent secret/public key mixups; `TweakKind` and `Layer` enums, 33-bit `LeafAddr`, per-layer bounded `Pos::new` (`tree < layer.trees()`, `leaf < layer.leaves()`, enforcing `tree == 0` at layer 3), and release-asserted 48-bit tree indices in `tweak` make out-of-range coordinates unrepresentable. | Caller-supplied 32-byte signing seeds (not entropy-tested by `from_seed`). |
| Verifier checks, lifecycle & planted-fault controls | Unit tests exercise WOTS+ nibble/checksum boundaries (`0..=480`), `parse_digest` 10-bit FORS index and 33-bit `leaf_addr` extraction, `advance_chains` zero/partial/early-finish/full lengths, per-layer `Pos::new` bounds, bit-0 flips across every signature region, wrong verifying keys, wrong lengths, stateful multi-key/trait lifecycle sequences (`Send`/`Sync`/`Clone`/`Copy`/`Eq`/`TryFrom`/`Debug`), and clockless multi-thread dispatch in `Pool`. [`tools/controls.py`](tools/controls.py) removes 16 protections one by one and verifies each targeted test actually runs and fails (with a 120 s timeout). | Predicates not listed in `tools/controls.py`. |
| Streaming I/O & stack budget | Tests verify slice-vs-reader equivalence across 15 length boundaries (`0` through `1 MiB + 19`) spanning the on-core `< 16` KiB stack fast path, the zero-copy `Pipeline` streaming path ($\ge 16$ KiB, zeroing each newly acquired room slice before `Read::read`), and the multi-core slice threshold ($\ge 512$ KiB), with fragmented reads, `EINTR` injection, mid-stream `Pipeline::abort` (`Event::Aborted`) recovery on `io::Error`, `u64::MAX` length-overflow checks, fail-stop checks on `Read` returning `n > buf.len()`, snooping checks across both stack and `Pipeline` rooms, re-entrant `Read` callbacks from both paths, and a bounded **128 KiB thread-stack** test on the optimized test profile. | Crash-only policy: recovering from panicking `Read` implementations or TLS-destructor calls via `catch_unwind` is not supported (internal panics abort rather than unwinding); unoptimized debug-build stack usage. |
| Startup randomness state | Tests check explicit `create` (refuses overwrite and dangling symlinks, `0o600` on Unix, distinct OS seeds), `initialize` (rejects directories, `/dev/null` non-regular files, missing, short, oversized-with-valid-magic, wrong-magic, and counter-exhausted files without modifying a byte; serializes 8 concurrent threads under `flock`), `mix` exact cross-check against Python and TypeScript, fresh-thread public `sign`, and draw counter exhaustion. | Unix-only signing boundary; filesystems without working advisory locks, symlinks to existing regular files in shared directories, `fork()` without `exec()` (pool aborts on PID change), and live VM snapshot cloning (callers must re-run `initialize`). |
| Process isolation (`cargo-nextest`) | Every test runs in its own process via `cargo-nextest` (`.config/nextest.toml`). Plain `cargo test` fails immediately on the sentinel test `aaa_require_nextest`. Separate fresh-process tests verify entry points initialize `blake3-servil`. | Doc examples run under `cargo test --doc` (rustdoc isolates each example in its own process). |
| Mutation testing | [`tools/mutants/check.py`](tools/mutants/check.py) runs `cargo-mutants` in `[profile.mutants]` (release optimization, no debug assertions or overflow checks) across all of `src/`. Every viable mutant must be caught by a test or justified in [`tools/mutants/known.txt`](tools/mutants/known.txt); timeouts and stale known entries both fail the gate. | Mutants classified in `tools/mutants/known.txt` (functional equivalence, dispatch/resource sizing, or directory-sync durability). |
| Self-check on imprinting | `Signet::imprint` and `imprint_reader` run `SignetId::verify_short` over every finished imprint (binding serialized salt `imprint[..16]` to `short[..16]` and recomputing all FORS + hypertree paths) before returning it (~25 µs, ~3.5% of imprinting time) and panic on mismatch. | External stream corruption before hashing; hardware faults that corrupt both imprinting and self-verification symmetrically. |
| Performance measurements | [`bench/`](bench/) measures wall time, core cycles, instructions, clock frequency, and background CPU load together via `bench-hashes`'s `clocks` crate, summarizing runs in exact integers. | Machines other than those explicitly reported; thermal or host interference on non-dedicated hardware. |
| Cross-family contract reviews | Round 1 (`0.1.0`) and Round 2 (`6e4ded7`) reviews by `openai/gpt-6.2-astra-pro`, plus Round 3 (`e1d6c88`) recall-calibrated (3/3 planted defects detected) contract-extraction review by a third distinct model family (`anthropic/claude-opus-5.5`), archived unedited in [`audits/`](audits/). | Independent human cryptographic review and formal security proof of the full BLINCS instantiation (not yet performed). |

## Timing and secret independence

BLINCS is designed so that no secret material steers a branch or memory index in its Rust code:

1. **Signing branches and indices depend only on public values.** The FORS tree indices (`fors_indices`), hypertree address (`leaf_addr`), chosen FORS leaf (`chosen_leaf`), Merkle sibling directions, and WOTS+ chain step counts (`digits(node)`) are all derived from `D`, `salt`, `randomizer`, and tree roots that are published in the signature itself.
2. **Secret material is only copied or hashed.** `seed`, `SecretKey`, `salt_key`, `randomizer_key`, `run_key`, `draw`, and unrevealed FORS/WOTS+ secrets are never branched on, sorted by, or used as array indices; they are passed directly into `blake3-servil`.
3. **Underlying hash kernels and hardware limits.** `blake3-servil` symbolically proves its assembly kernels branch- and address-independent of keys and inputs, while leaving CPU data-independent timing modes (Arm `DIT`, Intel `DOITM`) to the calling thread or OS. Power/frequency side channels (such as Hertzbleed) and data-dependent prefetchers without `DIT` (such as GoFetch on Apple M1–M3) sit outside software proofs; callers requiring hardware timing guarantees should enable `DIT`/`DOITM` at the thread or platform level.

## Bugs these steps found

Concrete defects found during development and cross-family reviews, and the checks that keep them from returning:

1. **Recycled `Pipeline` room bytes visible to `Read::read` (Round 2 review).** `content_from_reader` passed freshly acquired `Pipeline` rooms directly to `reader.read` without zeroing, exposing prior bytes to safe `Read` implementations. Fixed by zeroing every buffer slice before `read` in `content::fill_buf`; guarded by `test::reader_never_sees_previous_callers_bytes` across both the 16 KiB stack path and a 200 KiB `Pipeline` stream.
2. **Imprinting self-check did not independently bind `imprint[..16]` to `short[..16]` (Round 2 review).** `verify_short` hashed `short` without comparing `imprint.salt()` against `short[..16]`. Fixed in `SignetId::verify_short`; guarded by planted-fault control #5 in `tools/controls.py`.
3. **Mid-wave panic could hang the worker pool (Round 2 & Round 3 reviews).** A worker panic outside `wave.drain`, or an unsupported `fork()` without `exec()`, could leave `Pool::run` waiting forever on `remaining_workers`. Fixed by wrapping the full worker lifecycle and all fallback drain paths in `catch_unwind` -> `abort()`, and aborting on PID mismatch in `Pool::run`.
4. **Unchecked `u64::MAX` stream length and `Pipeline` abort event check (Round 2 & Round 3 reviews).** Fixed via `checked_add_stream_len` and explicit `Event::Aborted` matching after `pipe.abort(msg)`; guarded by `test::checked_constructors_reject_out_of_range_values`, `test::streaming_boundaries_and_fragmented_readers_match_slices`, and planted-fault control #8.
5. **Reference validation skipped under `python3 -O` (Round 2 review).** `reference/blincs.py` used `assert` for input length checks, which `-O` strips. Replaced with explicit `ValueError`/`TypeError` checks; guarded by the `python3 -O` check in `tools/land.py`.
6. **Missing `#[must_use]` on `verify`/`verify_reader` and loose `Pos::new` tree bound (Round 3 review).** A caller could write `vk.verify_reader(file, &sig)?;` and silently discard `false`, and `Pos::new` checked only `tree < 2^48` instead of exact per-layer bounds. Fixed with `#[must_use]` annotations and `tree < layer.trees()` (`tree == 0` at layer 3); guarded by `test::checked_constructors_reject_out_of_range_values`.
7. **Hypertree Merkle left/right rule and `FEW_ROOT` wording in `SPEC.md` (Blind TypeScript test & Round 3 review).** Clarified explicitly in `SPEC.md` so cold readers never have to infer hypertree sibling order or `FEW_ROOT` tweak fields.

```sh
cargo fmt -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo nextest run --locked
cargo test --doc --locked
python3 reference/blake3.py
python3 tools/counts.py
python3 tools/domain_sep.py
python3 tools/controls.py
python3 tools/mutants/check.py
python3 tools/land.py
```
